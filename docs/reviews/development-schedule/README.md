# 开发预计完成日期与日历排期 · 本地审阅

2026-10-21。本次代码已实现并完成本地验证，尚未发布。

## 最终行为

- 新增独立的“开发预计完成日期”，代表完成开发、自测并可提交验收的日期；所有工单类型适用。原“期望完成日期”保持独立。
- 管理员可在开始处理时选填，也可在详情页设置、调整或清空；顾问只读。历史工单默认留空，显示“待评估”。新设置的日期不得早于北京时间当天。
- 修改、清空已有日期，或重新确认退回工单的排期，必须填写原因。相同日期且无需重新评估时不重复写入事件或通知。
- 时间线记录操作人、旧日期、新日期和原因；首次随受理填写时合并进受理记录，只产生一组通知。
- 独立排期操作沿用站内提醒和钉钉通知队列，不改变工单状态及下一处理人；钉钉仍采用原来的简短更新通知，不向群内发送工单正文或改期原因。
- 只有“处理中”且预计日期早于当天的工单显示“已逾期 N 天”；“待受理／处理中”在当天显示“今日到期”。进入待验收、已完成后停止开发到期提示。
- 验收退回、重新打开时保留日期并提示重新评估；管理员可以填原因确认原日期。已完成工单不可修改排期。
- 列表增加预计日期、待评估／今日到期／已逾期筛选、预计日期升降序；空日期均排末尾。列表筛选、排序和页码随详情返回保留。
- “待评估”筛选包含待受理及处理中且日期为空的工单；待验收、已完成工单不计入待评估工作量。
- 工单 CSV 同时导出期望日期、预计日期、是否需重新评估；沟通记录 CSV 包含排期变更记录。导出沿用列表筛选。
- 开发日历默认“提交记录”，可切换到“预计完成”。按最新排期归日，包含待验收与已完成工单；未排期工单不占日历格，提供全局待评估数量及跳转入口。日期调整后移至新日期，原日期在时间线中保留。
- 日历视图、月份、日期、页码保留在 URL，从日历进入工单后可返回原位置。日历仍仅管理员可访问。
