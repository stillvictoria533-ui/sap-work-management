| P2 | 发送过程中新增编辑被清空 | 以发送快照判断正文是否可以清空，只移除已发送的附件，后写正文与新增附件保留；阻止重复并发提交。新建表单发送期间冻结编辑。 |
| P2 | 当前密码首尾空格被裁剪 | 当前密码与新密码均保留空格，API 回归验证成功改密及当前会话可用。 |

## 数据库与发布

新增迁移 `desk.0014_ticket_submission_fingerprint`，仅添加提交指纹列，不改写已有工单内容。旧记录无法可靠还原曾经上传的全部原始提交参数，指纹留空；对旧 key 的重试明确返回 409 并提示原工单，不猜测相同、不自动换 key 创建新工单。

发布时先停止现有 AI 调度并确认在途执行已退出，再按原运维流程备份、迁移，更新服务端与本机可信 AI worker 使用的同版 `ai_policy.py` 及 planner 提示词，验证前后端及 AI 边界版本一致后恢复现有调度。只有用户确认本次最终内容后才能部署；上线验收后按 [运维规则](../../OPERATIONS.md#上线后同步-github)提交/推送与上线版本一致的代码，并核实远端提交。

## 验证

最终自动化结果记录于同目录 `verification.json`。本地环境为 Python 3.14.3、Node 24.21.0、SQLite；真实 PostgreSQL 行锁测试由扩展后的 CI 执行。本轮没有把 SQLite 通过当作 PostgreSQL 并发验收，也没有连接真实 SAP/provider。

真实浏览器使用独立临时 SQLite 和两个模拟工单，AI、钉钉均关闭：

1. A 有草稿时直接切换地址到 B，取消后仍显示 A 且正文保留。
2. B 有正文及 `B-only.txt` 模拟附件时取消切换，正文与文件都保留；接受后 A 的正文、附件及选择列表均为空。
3. 另一会话新增模拟回复后出现更新提示；刷新可见该回复，B 的未发送正文及附件保留。
4. 1440px 桌面及 390px 移动视口无横向溢出，刷新和编辑入口可用。
