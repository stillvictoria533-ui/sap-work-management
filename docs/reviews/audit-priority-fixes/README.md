## 已确认缺陷

| 优先级 | 原问题 | 修复与回归证据 |
| --- | --- | --- |
| P1 | AI 可省略已授权的工厂、公司、年度 | 共享策略强制复合业务键及目标表支持的全部已知限制；MARC 限定 MATNR/WERKS，BKPF 限定 BUKRS/BELNR/GJAHR。预留、执行前校验与 CLI 参数共用该策略，旧 v1 scope 同样受约束。覆盖 DS4/QS4/PS4 及查询不落账场景。 |
| P1 | 在途旧改密请求覆盖管理员重置 | 改密在与重置相同的账号行锁内重读账号、会话版本和当前密码。可控交错验证重置密码与强制改密标记不会被旧请求覆盖；另有 PostgreSQL 双连接行锁回归。 |
| P1 | 同组件工单 ID 切换串入草稿和附件 | 参数切换也执行离开确认；成功切换重置全部编辑状态。回复、状态、排期、加载与加急回传校验当前工单，旧响应不再改写新工单。真实路由组件测试及浏览器确认取消/接受两条路径。 |
| P2 | 幂等键未绑定提交内容 | 指纹涵盖标题、系统、模块、类型、优先级、日期、描述和附件名称/大小/内容哈希。同键同内容复用，同键不同内容 409 并返回原工单入口；未创建重复工单或附件。 |
| P2 | 发送过程中新增编辑被清空 | 以发送快照判断正文是否可以清空，只移除已发送的附件，后写正文与新增附件保留；阻止重复并发提交。新建表单发送期间冻结编辑。 |
| P2 | 当前密码首尾空格被裁剪 | 当前密码与新密码均保留空格，API 回归验证成功改密及当前会话可用。 |
| P2 | 全部已读后继续请求失效第二页 | 操作成功回第一页并清除旧列表；其他客户端造成分页缩小时也从 404 回第一页。加入请求序号避免旧响应覆盖新筛选。 |
| P2（兼容模块） | 重试昨天的聊天绕过当日额度 | 用同一账号锁事务中生成的逐次入队审计时间计数，保留新问题数量限制；两次旧问题重试后第三次为 429。 |
| P3 | 特殊数字或超长 ID 触发 500 | 统一正整数解析，要求 ASCII、长度及数据库范围；筛选非法值返回 400，自由搜索保留文本语义。覆盖上标、全角、负数、零、超长与越界值。 |

## 验证

发布前的本地自动化结果保留于同目录 `verification.json`：当时环境为 Python 3.14.3、Node 24.21.0、SQLite，267 项通过、4 项环境相关跳过。随后本次发布在服务器隔离 PostgreSQL 环境中实际执行 171 项、0 跳过，并完成生产冒烟；扩展后的 GitHub CI 也已通过。新增证据独立记录于 `deployment-verification.json`，不改写此前的本地验证历史。

真实浏览器使用独立临时 SQLite 和两个模拟工单，AI、钉钉均关闭：

1. A 有草稿时直接切换地址到 B，取消后仍显示 A 且正文保留。
2. B 有正文及 `B-only.txt` 模拟附件时取消切换，正文与文件都保留；接受后 A 的正文、附件及选择列表均为空。
3. 另一会话新增模拟回复后出现更新提示；刷新可见该回复，B 的未发送正文及附件保留。
4. 1440px 桌面及 390px 移动视口无横向溢出，刷新和编辑入口可用。
