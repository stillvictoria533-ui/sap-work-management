# 本机备份与运维告警

- 每日北京时间 03:00–03:05 执行备份；启动错过的任务会补执行。
- 数据库和附件备份期间暂停 API、通知 worker 与聊天 worker，完成或失败后恢复原先运行的服务。
- 目录 `/opt/sapdesk/backups/daily/<UTC时间>`，包含数据库归档、附件归档、配置归档、SHA256SUMS 和完成标记。root 专用权限。
- 仅清理超过 14 天的合规已完成日备份，同时至少保留最近 7 份。升级备份、手动备份、不完整备份和异常目录不自动删除。
- 配置归档含密码和证书私钥，只能在本机 root 权限下使用；不要发送到聊天或普通文件共享。
- 每分钟检查：HTTPS/API/数据库健康、五个容器、磁盘、内存、CPU、备份时效、备份失败、证书临期与续期失败。
- Codex 认证卷独立持久化，未纳入每日配置归档；灾难恢复后需重新登录。不要删除 `sapdesk_codex-auth` 卷。
- CPU/内存达到 85% 且连续 5 次，服务连续 3 次失败，磁盘达到 80%，备份超过 30 小时未成功，证书不足 48 小时触发提醒。
- 相同未恢复告警最多每小时重复一次；新增/恢复情况会更新通知。钉钉接口接受不等于用户已读。
- 管理员机器人单独存于 `/etc/sapdesk-ops.env`，root:root 0600：`OPS_DINGTALK_TOKEN` 和 `OPS_DINGTALK_SECRET`；不复用顾问群。
- 测试渠道：使用 systemd 的 EnvironmentFile 启动 `python3 /opt/sapdesk/scripts/ops.py test-alert`，不要在命令行参数中传密钥。
- 查看任务：`systemctl list-timers 'sapdesk-*'`；`journalctl -u sapdesk-backup -u sapdesk-monitor`。
- 主机断电、网络全断时本机无法发送提醒；需要独立外部监测才能覆盖。这次未购买 COS，无异地副本。


## 2026-10-27 已发布的运行保障改进

本节描述已于 2026-10-27 上线的版本；现有任务时间和独立运维钉钉渠道不变。

### AI 运行状态与附件配额

- 管理员可在“运行状态”查看 AI 节点最近活动和扫描、等待/运行/重试/需处理数量、连续受阻分类、附件空间和本机备份状态；普通顾问不能访问。页面显示聚合数据，不展示工单正文、凭据或 SAP 查询结果。
- 原有每分钟扫描上报节点心跳和环境检查结果；正在处理工单时租约续签也会更新活动时间。默认心跳超过 300 秒、候选工单等待超过 600 秒或 24 小时内出现至少 3 次连续受阻时告警；需人工处理或依赖异常也会进入现有运维告警。依赖异常需连续三次采样。检查只验证本机文件/程序、固定身份配置格式和本机代理端口，**不证明模型登录、SAP 登录或实际查询成功**。监控不修改工单、查询范围或原有 AI 安全门禁。
- 默认单工单附件累计 256 MiB、同一提交人的所有工单累计 1 GiB、平台累计 2 GiB、附件所在文件系统至少预留 3 GiB。管理员为该提交人工单上传的附件也计入其配额；已有附件不删除，达到限制时仍可提交纯文字。单次上传的文件数及每文件大小等既有规则不变。设置项依次为 `ATTACHMENT_TICKET_LIMIT_BYTES`、`ATTACHMENT_OWNER_LIMIT_BYTES`、`ATTACHMENT_GLOBAL_LIMIT_BYTES`、`ATTACHMENT_MIN_FREE_BYTES`，单位字节，默认值见 `.env.example`；其中某项设为 `0` 可单独关闭对应限制或磁盘预留。配额使用数据库事务锁串行检查并发上传。
- 2026-10-27 的只读用量：8 个附件共 741,890 字节，单工单最大 140,215 字节，单提交人最大 403,636 字节；当时磁盘可用约 47.2 GiB。以上默认值留有增长空间，也为保留本机历史备份提供余量；需随实际业务与磁盘增长重新调整。

### 本机备份与隔离演练

- 每次备份停止服务前及停服务后检查空间：按数据库和附件实际占用的 110% 再加 1 GiB 估算；空间不足会中止。完成清单新增工单数、附件数、附件字节数，供恢复后核对。仅清理 14 天前的合规已完成日备份，并始终保留最近至少 7 份；未完成、手动、升级和异常目录不自动删除。
- 备份状态只向 API 只读挂载经过筛选的时间和布尔值；状态过期或不可读取时显示未知。演练失败和曾成功演练但超过 30 天未再演练会触发运维提醒。配置归档仍含密钥，只能由本机 root 管理；演练只核对其校验和，不解包或挂载该归档。
- **真实备份的恢复演练仍须按下方恢复授权要求，由管理员明确授权后执行。** 演练将校验归档，并在新建的 Docker 内部网络和空卷中恢复数据库与附件，迁移克隆数据库，检查测试账号登录、工单数量和首个附件下载；结束时按标签核对并清理本次资源。演练禁用 AI 和通知，不开放宿主机端口、不挂载生产数据卷。旧备份没有数量基线时无法比较原始数量；没有附件时不会执行附件下载检查。
- 在主机上由授权管理员将命令中的路径替换为具体已完成备份目录。只读验证不恢复数据；`drill` 会读取并在隔离容器中恢复该备份。

```sh
python3 /opt/sapdesk/scripts/restore_drill.py verify '/opt/sapdesk/backups/daily/<已完成备份目录>'
python3 /opt/sapdesk/scripts/restore_drill.py drill '/opt/sapdesk/backups/daily/<已授权备份目录>' --api-image sapdesk-api:latest --postgres-image postgres:17-alpine
```

- 本次只对真实最新备份做了只读完整性检查；完整恢复演练使用合成数据库与附件。按现有选择暂不配置异地存储，服务器及其磁盘同时损坏时，本机副本不能用于异地恢复。

## 恢复步骤（由管理员明确授权后执行）

1. 选择带 `manifest.json` 的完成备份，进入目录执行 `sha256sum -c SHA256SUMS`。
2. 为当前数据另做备份并暂停 API/worker。不要直接覆盖仍在使用的数据。
3. 在隔离 PostgreSQL 实例或新数据库中用 `pg_restore` 恢复 `database.dump`，验证表与数据后再切换；不要在未经确认的生产库执行清空操作。
4. 将 `attachments.tar.gz` 恢复到空的附件卷，保留容器应用 uid/gid 10001 的可读写权限。
5. 如需重建服务器，从 `configuration.tar.gz` 恢复配置并检查证书有效期；不得在不同环境直接暴露原密钥。
6. 启动服务，验证登录、工单、附件及健康接口。

发布验证包括归档目录可读、附件归档完整读取和校验和验证；不等同于已经进行过完整灾难恢复演练。

## 上线后同步 GitHub

每次新功能取得针对本次最终内容的发布确认、完成部署并通过上线验证后，必须同步更新 [项目 GitHub 仓库](https://github.com/stillvictoria533-ui/sap-work-management)。这是同次发布的必做收尾步骤，无需对已授权上线内容的同步重复确认；上线前的内容确认要求仍按根目录 [AGENTS.md](../AGENTS.md) 执行。

1. 整理与本次实际上线版本一致的源代码、测试、配置示例和相关文档，提交并推送到对应发布分支（当前为 `origin/main`）。工作区有其他未发布改动时，按文件或差异块选择本次内容，保留其他修改，不将本地项目快照等无关内容一并上传。
2. 遵守 `.gitignore`，不得提交真实环境配置、密码、密钥、证书私钥、数据库、附件、备份或运行数据。
3. 推送后读取 GitHub 远端分支，确认包含本次上线对应的提交；仅凭本地 `origin/main` 缓存或执行过推送命令不能宣称同步成功。
4. 在本次发布记录和交付说明中记录上线内容、上线时间（北京时间）、验证结果、GitHub 分支、提交号及同步结果。若同步失败，明确报告“已上线，GitHub 同步未完成”及原因，后续补齐后再标记发布收尾完成。
